# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

An MCP server that lets an MCP client (Claude Code, Claude Desktop) control a live Adobe After Effects project: build comps, add/animate layers, preview frames and render — all through tools that end up calling ExtendScript inside AE.

```
MCP client --stdio--> MCP server (src/, TypeScript) --HTTP 127.0.0.1 + token--> CEP panel in AE (panel/main.js) --cep.evalScript--> ExtendScript (host/ -> panel/host/host.jsx)
```

**Before changing code, follow `CONTRIBUTING.md`** (strict rules and the pre-merge checklist, each backed by an incident).

Full docs: `docs/setup.md` (install details, configuration, security, troubleshooting, updating), `INSTALL.md` (the install steps for AI agents), `README.md` (for people, plain words, kept short on purpose: CONTRIBUTING.md section 6 says which doc gets what), `docs/architecture.md` (layout, protocol, lifecycle), `docs/tools.md` (tool reference), `docs/development.md` (adding a tool, tests), `host/CLAUDE.md` (After Effects quirks), `docs/future.md` (Adobe's CEP → UXP move and what it would touch).

## Commands

```bash
npm install
npm run build       # clean; host/ -> panel/host/host.jsx (scripts/build-host.ts); src/ -> dist/ (tsc)
npm test            # build, then run everything in test/ (no After Effects needed)
npm run typecheck   # TypeScript 7: src/, tsconfig.tools.json (scripts/, test/, the skill driver) and tsconfig.host.json
```

Tests, `scripts/` and the skill driver are TypeScript that Node (22.18+) runs directly via type stripping: erasable syntax only (no enum/namespace/parameter properties), `.ts` import extensions, `import type` for types. The `test/mock-*.test.ts` files are `// @ts-nocheck` (loose AE fakes); the rest are strictly typed. There is no lint command and no single-test runner. `node test/live/run.ts --yes` runs the live tests against real AE (not part of `npm test`). `npm test` runs `test/run-all.ts`; run one file with `node test/<file>` after `npm run build`:
1. `static-checks.ts` — generated `host.jsx` is current and parses; ES3 lint of the compiled host (reports `build/host/<file>:<line>`); every schema is a `z.strictObject`; boots `dist/index.js` and diffs `tools/list` against the `C.<name> = function` commands, and `host/args.d.ts` against the schemas. `EXPECTED_TOOLS` must match the tool count; `tools/list` must carry no `$schema` (its size is printed).
2. `mock-host.test.ts` — layer/timeline/comp/marker commands (incl. insert_time, align_to_markers, trim_comp, update_marker, replace_source) against a mock AE DOM.
3. `mock-camera.test.ts` — camera maths, rigs, shake, lights, 3D layers, linking, 3D views against a mock DOM.
4. `mock-shapes.test.ts` — path (shape) values for masks/shape layers, ellipse vertex order, comp motion blur.
5. `mock-design.test.ts` — bounds/align/distribute maths, anchors, switches, solids, precompose leave-attributes, style/shape validation.
6. `mock-keyframes.test.ts` — edit_keyframes, copy_animation, stagger fidelity, separate dimensions, auto-orient (models the ease/bezier and roving quirks).
7. `mock-audio.test.ts` — the audio tools against a fake "Convert Audio to Keyframes" fed by synthesized tracks with known beats / peaks (beat detection within a frame, tempo, muting and work-area restore, sound cues from eased keyframes, add_sfx peak alignment and fades, duck_music spans / markers / expression and dips (run as JavaScript), equal-power fades and crossfades, story events in find_sound_cues, the volume alias).
8. `mock-motion.test.ts` — the motion tools against a fake DOM that evaluates the expressions they write (spring overshoot and exact landing, bounce never passing rest, reveal stagger order and end time, transition coverage at the cut, review rules).
9. `aerender-discovery.test.ts` — `findAerender` (`dist/render/aerender.js`) against fake install layouts.
10. `preview-image.test.ts` — preview PNG shrinking and contact sheets (`src/render/image.ts`).
11. `render-check.test.ts` — the after-render check and delivery (`src/render/check.ts`) against real ffmpeg on synthetic clips; skipped when ffmpeg is missing.
12. `server.test.ts` — the built server over stdio with a fake bridge and fake `aerender`: render lifecycle, preview wait, path sandboxing, run_jsx gate.
13. `panel.test.ts` — the real `panel/main.js` in a vm with a fake CEP/DOM, driven by the real `HttpBridge`: token, serial queue, dropping timed-out commands, TIMEOUT messages, Update button, bridge file lifecycle.
14. `update-script.test.ts` — `scripts/update.ts` against throwaway git repos: newest release tag (not `main`), refusing over local changes.
15. `register.test.ts` — `scripts/register.ts` (the installers' last step) with a throwaway HOME and a fake `claude`: Claude Desktop config merge (other servers, settings and `env` kept, broken JSON left alone, absolute node), Claude Code user scope, no-op when already registered, `AE_MCP_REGISTER=0`.
16. `check-script.test.ts` — `scripts/check.ts` (the installers' server check; `--ae` at the end of INSTALL.md) with a throwaway HOME, fake After Effects prefs files and a fake bridge: newest prefs file picked, the scripting setting read, each missing part named.
17. `docs.test.ts` — every relative link and `#section` in the Markdown resolves, `(docs/<file>.md, <Section>)` references in messages name a real section, and every `AE_*` variable the code reads is in `docs/setup.md`'s Configuration table.

## Layout

- `src/index.ts` entry (stdio, shutdown) · `src/server.ts` `createServer(bridge)` · `src/config.ts` every env var + version · `src/errors.ts` `ErrorCode`, `AeToolError` · `src/bridge.ts` `Bridge` + `HttpBridge` · `src/sandbox.ts` · `src/resources.ts` · `src/prompts.ts`
- `src/tools/registry.ts` — `ToolRegistry.bridged(name, desc, shape, { paths?, readOnly?, destructive?, idempotent?, openWorld?, tooLargeHint? })` (validate, sandbox `paths`, forward to the host command of the same name) and `ToolRegistry.tool(...)` for server-side logic. Schemas are zod 4 and every object is a `z.strictObject` (unknown keys rejected at any depth; `test/static-checks.ts` fails on a plain `z.object` in `src/`); adds a title + all four MCP annotations (non-read-only tools default to destructive), returns compact JSON and replaces results over `CHARACTER_LIMIT` (25k chars) with an error. `src/tools/schemas.ts` shared zod schemas.
- `src/tools/<group>.ts` ↔ `host/commands/<group>.ts`: inspect, project (+ import_footage, set_item), layers, timeline (+markers), audio (beat_markers, audio_react, find_sound_cues, add_sfx, duck_music), motion (animate, text_reveal, transition, review_motion), masks, animate (+`text.jsx`), scene3d, design (align, anchors, add_shape, layer styles, text to shapes), output (preview/render), scripting (run_jsx).
- `src/render/aerender.ts` (find aerender / written file), `src/render/manager.ts` (`RenderManager`: progress, ETA, GPU-failure detection, deliver / verify phases), `src/render/check.ts` (ffmpeg: black / frozen / silent spans, loudness, deliver), `src/render/image.ts` (shrink previews, contact sheets).
- `host/` is TypeScript (only `json.jsx`, the vendored JSON polyfill, is JavaScript), strict, type-checked by TypeScript 7 (`tsconfig.host.json`) against AE 22.0 + ES3 lib types (`types-for-adobe`) and compiled to ES5 in `build/host/` by TypeScript 5.9 (`typescript-es5`, `tsconfig.host-emit.json`: TypeScript 7 has no ES5 output; npm scripts call each `tsc` by path, never a bare `tsc`). Commands take `a: Args["<tool>"]`: `host/args.d.ts` is generated from the server's tool schemas by `scripts/host-args.ts` during `npm run build` (static check: never stale; `HostArgs` in `host/env.d.ts` covers what the server calls with other arguments). `host/env.d.ts` also declares what the AE 22.0 types lack (newer APIs, `JSON`, `app.path`) and makes `property()` return `any` (what it returns depends on the match name). `has()` is a type guard and `need()` an assertion, so `if (has(a, "time"))` narrows `a.time`. Script mode: all top-level names are global and shared (type names merge with AE/ScriptUI globals, so prefix them: `CamView`, `LayerBounds`). Details in `docs/development.md`.
- `host/` — ExtendScript sources: `json.jsx` polyfill, `core/` helpers, `commands/`, `dispatch.ts`. `scripts/build-host.ts` wraps them in one closure (`var AEM = (function () { var C = {}; ... })()`) and writes `panel/host/host.jsx`, which is **generated and gitignored — never edit it**. New host files go in `MODULES` in the build script; top-level names must be unique across `host/` (the build checks).
- `scripts/` — `install.sh` / `install.ps1` (the installers: build, `check.ts`, copy `panel/` to the CEP folder, allow unsigned panels, `register.ts`) · `update.ts` (newest release tag, then the installer; how users install and what the panel's Update button runs: developers use the installer instead) · `check.ts` (server starts; `--ae` also the scripting setting and the panel) · `register.ts` (Claude Desktop / Claude Code) · `build-host.ts`, `host-args.ts` (the host build) · `mcp-client.ts` (stdio client for scripts and live tests). `.claude/skills/run-ae-motion/` drives a live After Effects (call tools, previews, hot-reload `host.jsx`).
- `test/live/run.ts` — live tests: the behaviours the mocks model, checked against real AE through the built server (`node test/live/run.ts --yes`; replaces the open project). Not in `npm test` (CI has no AE); run before a release and after `host/` or `panel/` changes. `scripts/mcp-client.ts` is the stdio MCP client the live tests use.
- `panel/` — the CEP extension as installed (manifest, `main.js` HTTP bridge with serial queue and the Update button, `index.html`). The installers add `install.json` (repo path + `PATH`, since AE started from the Dock cannot find Homebrew/nvm `node`); the installers also check the built server starts (`scripts/check.ts`; `--ae` also reads After Effects' scripting setting from its prefs file, read only, and calls `get_project` through the panel) and register the server with Claude Desktop and Claude Code at user scope (`scripts/register.ts`, idempotent; `AE_MCP_REGISTER=0` skips it); installing goes through `scripts/update.ts` (README, INSTALL.md) so a fresh install is the newest release, never `main` that the Update button would then move back from; the button runs `scripts/update.ts` there (checks out the newest `vX.Y.Z` tag, never `main`; refuses over local changes) + the installer, `$.evalFile`s the new host.jsx and reloads the panel. The queue drops a command whose request closed before it started (the server timed out) and says so with `drops: true` in the bridge file; `HttpBridge` explains a `TIMEOUT` from its own unanswered earlier commands and `/health` (which can't answer while ExtendScript runs: silence means AE is busy).

## Versions and updates

- One version in `package.json` and `panel/CSXS/manifest.xml` (two places); the build stamps it into host.jsx as `AEM.version`; `test/static-checks.ts` enforces all three. Releases are git tags `vX.Y.Z` plus a `CHANGELOG.md` entry (`docs/development.md` → Releasing).
- `src/usage.ts`: the token meter. `ToolRegistry.tool` records every result (text ~3.6 chars/token, images w*h/750 from the PNG header), `slimToolList` records the tool-definition size; written to `usage/<pid>.json` next to the bridge file, read by the panel every 2 s (week-old files pruned). Estimates of what ae-motion sends, not the client's bill.
- `src/update.ts`: daily background check of GitHub's tags API (`AE_MCP_UPDATE_CHECK=0` off, `AE_MCP_UPDATE_URL` override), cached in `update.json` next to the bridge file; `get_project` adds an `update` note, `check_for_updates` (server-only tool) asks directly, the panel reads the cache and shows an update line. Tests keep the check off by default (no real network).

## Rules

- **Adding a tool touches both ends**: register it in `src/tools/<group>.ts` and implement `C.<name>` in `host/commands/<group>.ts`; bump `EXPECTED_TOOLS`; add it to `docs/tools.md` (the README lists no tools). Step by step: `docs/development.md`.
- **`host/` must compile to ES3**: `const`/`let`, arrows and template strings are lowered by TypeScript; spread, destructuring, `for...of`, classes and async need helpers, so don't use them. The ES3 standard library types make ES5+ methods (`forEach`, `map`, `.includes`, `.trim`, `Object.keys`...) compile errors. No `Array.prototype.indexOf`. The lint runs on the compiled output in `build/host/`. The lint scans comments too (backticks, `...`). Don't type ` `/` ` escapes with the Write tool — it has turned them into raw characters; the lint catches that.
- **Paths**: only arguments listed in `paths` are sandboxed (`assertAllowed` against `AE_MCP_ALLOWED_DIRS`, default home + temp) and slash-normalised (`toAe`). List every path argument there, and nothing that isn't a path (a match name was once sandboxed by mistake).
- **Errors**: always `{error:{code,message,hint}}` with `code` one of `NOT_FOUND`, `BAD_ARGS`, `AE_ERROR`, `BRIDGE_DOWN`, `TIMEOUT`, `FORBIDDEN`, `UNSUPPORTED`, `EXISTS`. Throw `AeToolError` in TypeScript, `fail(code, message, hint)` in ExtendScript. Schema failures are caught by the SDK (v2, `@modelcontextprotocol/server`) before any handler; `toolInputErrors` (`src/tools/registry.ts`) rewrites them into the same format (`BAD_ARGS`, message rebuilt from the zod issues, not the SDK's text) and an unknown tool into `NOT_FOUND`. It, `slimToolList` and the per-client `initialize` wrap the SDK's private `_requestHandlers` map: after an SDK upgrade, diff `tools/list` and the error texts against the previous version.
- **Undo**: every mutating command runs in one undo group (`host/dispatch.ts`); read-only commands are listed in `READONLY` there.
- **Token cost**: tool definitions go to the model on every request. Keep descriptions short and share schemas from `src/tools/schemas.ts`; `npm test` prints the tool list's size (no hard limit). Previews are shrunk before they go to the model (`src/render/image.ts`; images are the most expensive results). Advertised schemas are slimmed in `slimToolList` (refs inlined, bounds dropped; zod still enforces them). Results leave out default values (`layerInfo`, `layerBrief` for get_comp rows, `keyInfo`), which `SERVER_INSTRUCTIONS` in `src/prompts.ts` documents for clients; `list_properties` hides noise groups (`walkShows`) and `review_motion` groups issues unless `all`. Every group is registered; `ToolVisibility` (`src/tools/index.ts`) decides what `tools/list` shows: `pickToolsForClient` (`src/server.ts`) shows Claude Code everything (it defers definitions) and other clients core, unless `AE_MCP_TOOLSETS` (`src/config.ts`) chooses; the hidden tools are named in the instructions, and `load_tools` or a `batch` step naming one (`ToolRegistry.autoload`) shows its group. Test harnesses pin `AE_MCP_TOOLSETS=all`. `batch` (`src/tools/batch.ts`, server only) runs bridged tools from `ToolRegistry.bridgedTools` with `"$N.path"` or named (`as` / `"$name.path"`) references and per-tool `defaults` (shared args sent once); mutating commands return `layerRef` / `layerTiming` / `layerFieldsSet` (`host/core/describe.ts`), not full layer info.
- Conventions for tools: time in seconds, sizes in pixels, colors `[r,g,b]` 0–1, scale in percent; comps/layers by numeric id; properties by alias (`position|scale|rotation|opacity|anchor`) or match-name arrays.
- Changes to `host/` or `panel/` need `npm run build` **and** the installer re-run (`scripts/install.sh` / `.ps1`) plus reopening the panel. `host/` is the first place to look when a tool behaves differently on another AE version.

## After Effects quirks

40 behaviours of After Effects found in live testing, which `host/` and the mocks rely on, are in `host/CLAUDE.md`
(Claude Code loads it when you work in `host/`). **Read it before changing `host/` or a mock in `test/`**, and add new
quirks there.

## Verification status

Every tool was checked by hand against real AE (26.3, macOS), camera move directions confirmed from rendered pixels. Blend modes (NORMAL, ADD, MULTIPLY, SCREEN, DIFFERENCE) and adjustment layers were checked from preview pixels in AE 26.3 (a live test keeps checking them). `run_jsx` is checked live too (refused when disabled; values, AE objects, thrown and parse errors when enabled). Gaps: the Windows installer, After Effects before 26.3. The restructure into `src/tools/` + `host/` was verified by tests, an identical `tools/list`, and a function-level diff of the generated `host.jsx`, then smoke-tested live in AE 26.3 (all but render_start). A green `npm test` doesn't prove a change works in real AE.
